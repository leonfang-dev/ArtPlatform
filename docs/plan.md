# Roblox 一站式创作平台实施计划

状态：方案草案 · 2026-10-11

## 1. 产品方向

目标用户是希望用 AI 加快 Roblox 美术与场景制作的独立创作者和小团队。核心流程：

创意与风格板 → Lovart 式画布生成和局部编辑 → 场景布局与模块资产三视图 → Meshy 多图生成单个粗模 → Roblox Studio 导入 → Codex 通过 Studio MCP 按布局搭建 → 特效编辑与真机预览。

这里的“Lovart 式”指单项目画布、多候选并排、局部编辑、图层与风格一致性，不表示必须依赖 Lovart 的内部模型或 API。具体图像模型采用可替换适配器。

**关键拆分**：三视图用于一个道具或建筑模块的多角度重建。Meshy 官方 Multi-Image to 3D 接收同一物体的 1–4 张图，不能直接将一张完整关卡三视图变成准确、可玩的 Roblox 地图。完整场景需要另存一份布局数据，由 Codex 通过 MCP 在 Studio 中摆放模块、生成基础几何与地形，并检查可通行性。

## 2. 一个可展示的端到端样例

以“魔法森林入口”为示范场景：

1. 在画布中描述风格与玩法，生成正面/侧面/背面一致的“石门”和“路灯”模块，以及场景氛围图。
2. 用户挑选并局部修改图片，确认每个模块的三视图与比例；画出俯视布局，标注出生点、道路、石门和路灯锚点。
3. 将每个模块的三视图分别送入 Meshy 生成粗模，检查轮廓、比例、面数、纹理与碰撞需求。
4. 使用 Roblox Studio Importer 导入模型。保存资产 ID、缩放、朝向和用途清单。
5. Codex 通过 Roblox Studio MCP 读取现有场景，提出搭建预览，按布局摆放模块和原生 Part/Terrain，运行基础检查，用户验收后保留改动。
6. 为石门添加“传送门开启”特效，使用粒子 + Beam + 灯光的可编辑配方；桌面和移动端预览。
7. 保存图片版本、Meshy 任务、模型文件、场景布局、特效配方与 Studio 对象的关联，便于局部重做。

## 3. 模块设计与交付顺序

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| A. 集成验证 | 手动完成一次上述端到端样例；记录格式、导入、MCP 与性能问题 | 一个场景可在 Studio 运行，所有素材有来源和版本记录 |
| B. 图片工作台 | 项目画布、风格板、候选对比、局部重绘、去背景、三视图一致性检查、导出 | 从一次提示到批准三视图，允许只重做单一视角 |
| C. 场景流水线 | 模块清单、Meshy 任务适配器、模型检验、Studio 导入、布局 JSON、Codex MCP 搭建指令 | 至少两个模块能按布局导入与摆放，并可局部重建 |
| D. 特效工作台 | 模板、分层时间轴、参数编辑、预览、性能档位、配方复用 | 传送门/攻击命中/环境氛围三类特效可编辑、可撤销 |
| E. 协作与发布 | 资产关系、版本比较、团队共享、发布检查 | 可追溯每个 Studio 对象来自哪个资产版本 |

先手工跑通 A，再把高频手工步骤产品化。周期粗估：A 1–2 周，B 2–4 周，C 3–5 周，D 2–4 周；以集成验证结果修订。

## 4. 图片工作台：参考 Lovart 的交互

无限画布中可摆放文字、参考图、候选图、三视图组和场景草图。用户可点击某个对象进行局部编辑，保留满意部分；使用项目风格板固定颜色、材质、光照和比例语言。每次生成形成非破坏式新版本，支持并排对比和回退。三视图要标记正/侧/背、主体一致性、背景清洁度与比例参照，导出单独图片而非拼图。

图像模型为可替换提供方。平台保存提示词、参考图、模型版本、生成参数、许可信息和输出哈希。图片进入 Roblox 前检查格式、尺寸、透明通道和可读性，并显示审核状态。AI 输出仍需人工挑选与确认。

## 5. 场景流水线：三视图 → Meshy → Codex MCP

### 数据结构

- **场景蓝图**：区域、尺寸单位、主路径、出生点、目标点、相机参考、模块锚点及约束。可从概念图辅助推断，但最终由用户确认。
- **模块包**：同一物体的正/侧/背视图、期望尺寸、Meshy 任务 ID、模型版本、格式、面数、纹理、碰撞方式和授权来源。
- **Studio 清单**：Roblox 资产 ID、坐标系转换、缩放、Pivot、放置位置与项目对象 ID。

### 流程约束

Meshy Multi-Image to 3D 的输入图必须描述同一物体；首张设为正面。优先导出 FBX 或 GLB，由 Studio Importer 预览并确认警告。模型只是粗模，需检查拓扑、纹理、比例和碰撞；复杂场景保留为独立模块，重复模块复用资产。

Codex 经 Studio MCP 在开放的 Studio 会话中读取场景、执行受控 Luau、摆放与测试。操作前生成差异预览；每批写入带项目标签，支持撤销与局部重试。场景中的可玩路径、碰撞、出生点、性能和视觉质量以 Studio 测试验收。不能将 Meshy 模型输出等同于完成关卡。

## 6. 特效方向

建议先做 **“意图 + 分层时间轴”**，让没有特效经验的创作者也能做出 Roblox 原生且可调的效果。输入是“传送门开启”“剑击命中”“森林萤火”等意图，加一张风格参考图或场景对象；输出是以下可单独编辑的层：

- 起势：短暂发光、蓄力或吸引注意。
- 主体：粒子、Beam 或 Trail 的形状、方向、速度与颜色。
- 冲击：瞬时爆发、闪光、扩散圈。
- 余韵：残留粒子、渐隐光与环境氛围。

每层有开始时间、持续时间、挂点、贴图和强度。编辑器提供低/中/高性能档位、实时预览、慢放、循环和移动端预算提示。用户可以只替换贴图或某一层，不重做整段特效。AI 可从描述与风格板推荐配方，但最终输出为 ParticleEmitter、Beam、Trail、灯光等 Roblox 原生对象。首批模板：传送门、武器命中、环境氛围；后续扩展技能弹道、拾取反馈和天气。

配方 schema 显式标版本；预览与应用共用解释器；场景对象保存配方 ID。验收要求：三类模板五分钟内可完成初版，重开 Studio 后可再次编辑，撤销不留孤立对象，缺失挂点和贴图有提示，并记录移动设备帧率与内存变化。

## 7. 技术架构

- Web/桌面画布：图像项目、场景蓝图、资产关系与生成任务。
- 生成适配层：图像服务、Meshy API；任务排队、状态轮询、失败重试、成本上限。
- 本地项目清单：版本化 JSON，保存场景蓝图、模块包与特效配方，供 Git 追踪。
- Roblox Studio 插件：对象选择、模型检查、特效编辑和预览。
- Codex + Studio MCP：按批准的蓝图批量搭建、检查和迭代；不把任意 AI 代码作为无预览的自动发布步骤。
- Open Cloud：用于需要时的资产上传和状态跟踪；密钥只存安全配置，不入仓库。

## 8. 版本管理

main 保持可运行；feature/* 分支开发，Pull Request 合并。配方与蓝图 JSON、提示词模板、设计文档及小型授权测试素材纳入 Git；大型生成图片与模型放对象存储，清单保留版本、哈希与来源。配方 schema 和场景蓝图均提供迁移版本。CI 在代码出现后加入 schema 校验、Luau 静态检查、插件构建与场景烟测。Studio 视觉质量及移动端性能人工验收。发布用语义版本标签；素材上传、插件发布和游戏发布分开操作。

## 9. 风险与验证

| 风险 | 验证与处理 |
| --- | --- |
| 三视图不一致导致 Meshy 粗模失真 | 三视图一致性检查；允许重生成单视角；导入前人工预览 |
| 把场景概念图误当精确布局 | 独立的俯视蓝图与尺寸锚点，用户确认后搭建 |
| 模型比例、碰撞与性能不合格 | Importer 检查、规模与面数预算、碰撞替代体、移动端实测 |
| 图片和模型审核/授权问题 | 保存来源、许可及审核状态，允许替换素材 |
| Studio MCP 自动操作误改场景 | 批次标签、差异预览、撤销与局部重试 |
| 特效在移动端过重 | 质量档、贴图复用、按需触发、真机采样 |
| 外部 API 成本与版本变化 | 适配层、成本上限、固定任务版本、手动导入路径 |

## 10. 近期行动

先选一个小型样例场景与两个模块，手动打通三视图、Meshy、Studio 导入、Codex MCP 搭建和一个特效。记录每步耗时、失败点和人工修正次数，再确定图片画布与特效编辑器的具体需求。
